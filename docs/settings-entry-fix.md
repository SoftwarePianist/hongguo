# 设置页入口修复：从「白色色块」到原生条目

> 适用版本：海外版 `com.phoenix.read.oversea.gp` **7.3.7.32**
> 修复文件：`hooks/Hooks.kt`
> 验证设备：OnePlus PLK110（ColorOS，root + LSPosed）

## 1. 问题现象

红果设置页（`SettingsActivity`）里的模块入口从「正常条目」变成了**一个白色色块**：
只有一个空白色矩形 + 右侧箭头，看不到任何文字，点击也无法打开面板。

## 2. 根因

问题有**两层**，必须分开看。

### 2.1 第一层：原生注入整条链路失效 → 退化到兜底布局

模块原本的做法是把一个数据项（item）直接插进设置页的列表里，这样入口天然就是原生样式。
但 7.3.7.32 把这条链路整个打散了：

| 环节 | 模块表里的值 | 7.3.7.32 实际情况 |
|:---|:---|:---|
| 列表构建方法 | `e1` / `f1` | `k1(adapter)` / `l1(adapter)` |
| 条目类 | `vr5.e` | **`vr5.e` 已不存在**，实际是 `a74.*`（`a74.c`=账号与安全、`a74.a`=关于红果…）|
| 点击处理类 | `vr5.b` | `vr5.b` 已不存在 |

日志直接印证：

```
[WARN] 原生设置列表 Hook 未找到 | profile=OVERSEA-7.3.7.32 | methods=[e1, f1]
[WARN] 原生设置数据项注入失败(vr5.e): java.lang.ClassNotFoundException: vr5.e
```

注入失败后，模块退回「固定布局 footer 兜底」：把设置页原有内容整体搬进一个 `FrameLayout`，
再在底部追加一条自绘的 `LinearLayout` 当作入口。

### 2.2 第二层：兜底入口「白底白字」= 用户看到的白色色块

兜底入口的原始实现有两个致命假设：

```kotlin
// 背景：透明，指望父容器是深色
background = RippleDrawable(ripple, ColorDrawable(Color.TRANSPARENT), mask)
// 文字色：从隔壁设置项「猜」
val textColor = nearestSettingsTextColor(parent, p.text)
```

而海外版设置页**底部本来就有 App 自带的白色区域**（「《隐私政策及简明版》」那一块，深色主题下也是白底）。
于是：

- 入口背景透明 → 直接露出底下的白色；
- 文字色取自上面的设置项（深色主题 → 近白色）；
- **白字压白底 → 什么都看不见，只剩一个白色色块。**

UI dump 证实文字其实是存在的，只是不可见：

```
<node text="模块设置" class="android.widget.TextView" bounds="[63,2576][1111,2772]" />
```

## 3. 修复方案

### 3.1 列表方法：改为运行时探测（不再依赖混淆名）

`SettingsActivity` 每次发版都会重排方法名，但「返回 `List` 的带参方法」这个**结构特征**很稳定
（设置页必然有一两个方法负责产出条目列表）。所以：

```kotlin
val listMethods = settingsClass.declaredMethods
    .filter { java.util.List::class.java.isAssignableFrom(it.returnType) && it.parameterCount in 1..2 }
    .sortedByDescending { it.name in settingsSpec.listMethods }  // 表内名字命中优先
```

实测命中 `k1` / `l1`，日志标记为「运行时探测」。

### 3.2 条目：模板复制注入（不写死类名/字段名）

思路：不自己造条目，而是**拿同页已有的普通条目当模板，复制一个同构条目**。

```
1. 在返回的列表里挑模板：
   - 有标题（字段 e，或第一个非空 CharSequence 字段）
   - 有点击回调（字段 n，或第一个「接口类型且已赋值」的字段）
   - 不是开关项（开关字段 o 的值不是 AtomicBoolean）
   - 能就地构造（无参构造，或单参构造且参数可由 Activity / ApplicationContext 赋值）
2. 用模板的类构造同构实例
3. 改标题字段 → 「模块设置」
4. 用 java.lang.reflect.Proxy 实现回调接口，点击时打开模块面板
5. 插到模板所在位置
```

实测结果：

```
[INFO] 原生设置项已动态注入: 模板=a74.c「账号与安全」 index=1 | 标题字段=e
```

`a74.c` 的原始实现恰好是最理想的模板形态：

```java
public final class a extends n26.e {
    public a(AbsActivity act) {
        this.e = act.getString(...);   // 标题
        this.i = true;                 // 显示箭头
        this.n = new C0000a(act);      // 点击回调（接口 n26.a）
    }
}
```

**踩过的两个坑（务必保留）**：

1. **开关判据必须是「字段值」而非「字段类型」**。开关字段 `o` 声明在基类 `n26.e` 上，
   每个条目都有这个字段，只有开关项才有值。按类型筛会把**所有**条目都排除，报「未找到可用模板条目」。
2. **模板必须能就地构造**。第一版挑中了「清理缓存」（`a74.l`），它的构造是 `(Activity, adapter)`
   双参，复制失败。现在把「构造可行性」纳入模板筛选条件。

### 3.3 兜底入口：不透明背景 + 按背景算对比色

即使将来动态注入也失败，兜底也不能再出现白块：

```kotlin
val bgColor = p.surface                      // 模块自己的卡片色（深浅主题成对）
val textColor = readableTextOn(bgColor, hostText)  // 对比不足则按背景明暗切换
```

另外给兜底容器铺上宿主底色（`resolveHostSurfaceColor`），避免入口「悬」在 App 的白色区域上。

## 5. 残留说明

- ~~模板选择是启发式的（第一个满足条件的可点击普通条目），入口位置取决于该条目在列表中的位置。~~

- `n26.e` / `a74.*` 这类名字下次发版仍可能变，但动态注入全程不引用它们——只用
  「结构特征 + 反射」，因此对发版免疫。

## 6. 第二轮修复：入口置顶 + 卡片圆角

### 6.1 现象

修复后入口能显示了，但还有两处不对：

1. 入口**不在最上面**，而是压在「清理缓存」下面（旧版本位于最顶部）；
2. 入口是**直角**的，不像宿主条目那样是圆角卡片（旧版本是圆角）。

### 6.2 根因

**顺序**：动态注入当初是「插到模板条目之前」——`list.add(indexOf(template), item)`。
本意是想挨着普通条目好继承样式，结果位置被模板绑死：模板是 `a74.c`「账号与安全」，
于是入口落在 index 1（「清理缓存」index 0 之后）。旧实现用的是 `list.add(0, item)`。

**圆角**：这是 7.3.7.32 的一处结构性变化。旧版（7.3.5.32）的圆角写在**条目类自己**的
`a/b/c` 字段上，所以旧代码里 `setFieldValue(item, "a"/"b"/"c", true)` 就能出圆角；
7.3.7.32 改成了**分组驱动**，样式字段搬到了 item 的 abstract 父类
（实测 `p26.a$a`，即 `n26.e` 的父类）上，语义为：

| 字段 | 含义 | onBind 行为 |
|:---|:---|:---|
| `a` | 属于分组卡片 | true 才走卡片分支，否则上下圆角背景直接 `GONE` |
| `b` | 组内首项 | 顶部圆角背景 `n` 可见 |
| `c` | 组内末项 | 底部圆角背景 `o` 可见 |
| `d` | 分组标签文本 | 非空时在首项旁显示 |

这三个字段由分组管理器（实测 `p26.a`）的 `c()` 统一赋值：
把组内所有条目刷成 `a=true,b=false,c=false`，再让首项 `b=true`、末项 `c=true`，
在数据构建结束时调用一次。

而我们的条目是 hook 列表方法**返回之后**才塞进去的：没进任何分组，也没同步这三个字段，
`onBind` 于是走 else 分支把上下圆角背景全部 `GONE` —— 表现就是直角。

### 6.3 修法

`injectNativeSettingsItemDynamic` 两处改动：

1. **位置**：`list.add(0, item)`，固定置顶（与旧版一致），不再跟随模板。
2. **样式**：新增 `applyGroupCardStyle(item, list)`，把条目按**独立卡片**置位 ——
   `a=b=c=true`、`d=""`。

为什么是「独立卡片」而不是「挂进某个分组」：独立卡片天然上下都圆角，且**不需要改动
任何现有条目**——分组结构没变，其它条目的首/末项状态本来就是对的。更关键的是，
它不进分组，宿主之后再重算分组（`onResume` 里的 `n1()` 就会调 `p26.a.c()`）也**覆盖不到它**，
比挂进别人分组更稳。

字段名做了两级兜底，防下次发版漂移：

- 主路径：按名取 `a/b/c`（R8 按声明顺序分配字母：父类占 `a~d`，子类从 `e` 往后接着排，
  这正是 `n26.e` 字段从 `e` 开头的原因，顺序稳定因此名字大概率稳定）；
- 兜底：取 item 的 abstract 父类**声明顺序前三个 boolean**，但要求列表里已存在被置位的
  条目（证明宿主确实在用这套机制），否则宁可跳过——避免把国内版旧结构的无关字段改成 true。
